# 灵境奇旅 · Client 项目骨架

> 本文档用于 `client/`（游客端）成员同步与拆分开发任务。
> 依据：`CLIENT_HANDOFF.md`、`开发需求文档v1.md`、产品原型交付页及「全部模块界面」截图。
> 说明：本文只描述**游客端（Client）**模块；管理端（Admin）仅在与 Client 有交集的边界处标注，不在本文展开。

---

## 0. 总览

### 0.1 一句话目标
3–5 分钟可演示的数字景区 Demo：游客在第三人称 3D 西湖中探索、切换中秋主题、完成猜灯谜并获得纪念卡；管理端发布主题或互动点配置后，游客端同步变化。

### 0.2 职责边界（务必遵守）
- 只调用 `GET /api/client/config`，**禁止**调用任何 `/api/admin/*`。
- 类型与固定 ID 从 `@hackday/contracts` 导入（`ScenicExperienceConfig`、`WEST_LAKE_IDS`），**禁止**自建 `Theme / Scene / InteractionPoint / MiniGame / Reward` 模型。
- `admin/` 的页面、组件、服务、样式不导入、不修改。
- 游客状态 `UserProgress` 与公共景区配置严格分离；管理端发布不得清空游客进度。

### 0.3 数据入口
```ts
import type { ScenicExperienceConfig } from "@hackday/contracts";

let config: ScenicExperienceConfig;

async function fetchConfig() {
  return fetch("http://127.0.0.1:8787/api/client/config").then((r) => r.json());
}

async function refreshIfVersionChanged() {
  const next = await fetchConfig();
  if (!config || next.version !== config.version) {
    config = next;
    applyTheme(config.themes.find((t) => t.id === config.activeThemeId));
    renderHotspots(config.interactionPoints.filter((p) => p.enabled));
  }
}
setInterval(refreshIfVersionChanged, 2000);
```

## 1. 入口模块

### 1.1 首页（APP 首页）
- 目的：进入景区前建立预期，承载搜索和推荐入口。
- 核心元素：
  - APP 名 + 口号（如「让每一步风景，都成为故事」）
  - 定位 + 城市文旅宣传语 / 古诗词
  - 搜索框（山岳景区、博物馆、展览、人文古迹…）
  - 今日推荐（分类，每类可 3D 云游）
  - 推荐（热门去处、新展速递、附近好玩）
  - 专题（文明探源、艺术流派、亲子研学…）
  - 社区（精选个展、达人游记、测评分享）
  - 广告位（新展览、景区活动）
  - 底部导航（个人空间 / 首页 / 我的）
- 状态：无特殊状态。
- 数据：`ScenicArea`、推荐列表（Demo 可 Mock）。
- 验收：可搜索「西湖」进入详情页；无死链。

### 1.2 景区详情页（西湖详情）
- 目的：建立场景/主题/互动预期，进入 3D 景区。
- 核心元素：
  - 景区名、评分、位置、简介
  - 附近景点（按距离排序 + 查看更多）
  - 线上全景漫游（虚拟游览）入口
  - 线下智游向导（需到场）入口
  - 热门浏览路线（经典景点路线、热门徒步路线）
  - 热门游记（用户文字 + 扫描重建的 3D 物体/空间 + 时间）
  - 个人收藏
  - 「开启 3D 云游 / 立即进入」按钮
- 状态：进入按钮 → 场景加载页。
- 数据：`ScenicArea`、`scenes`、`spots`、`availableThemeIds`。
- 验收：西湖介绍完整；进入按钮可跳转场景加载。

## 2. 探索模块

### 2.1 场景加载（Loading）
- 目的：避免白屏，让用户知道正在进入哪个场景。
- 核心元素：场景名、加载进度、定位状态、失败重试。
- 状态：加载中 → 成功进入 / 失败（重试、返回）。
- 验收：显示进度与定位状态；失败有降级路径（静态场景/备用视频）。

### 2.2 线上全景漫游（3D 探索，核心）
- 目的：第三人称 3D 西湖探索。
- 核心元素（对齐原型 8 标注）：
  1. 品牌/当前场景（`ScenicArea.name`、`Scene.name`）
  2. 方向罗盘 + 目标距离（朝向、目标名、动态距离）
  3. 当前任务折叠条（一个任务标题 + 一句提示）
  4. 三段式环境热点（景点/游戏/传送）
  5. 游客角色 + 定位同步（真实位置 → 场景坐标 → 平滑移动）
  6. 自适应主操作按钮（`了解这里` / `开始挑战` / `进入场景`）
  7. 主题入口（默认/中秋/国庆）
  8. 助手搭档（跟随、领路、提示）
- 第三人称规则：
  - 镜头在角色后上方，角色保持在画面中下部
  - 助手在侧前方，跟随/短距离领路/面向目标
  - 角色与助手不可穿过建筑、水面、场景边界
  - 手机非控件区滑动观察；桌面鼠标观察
  - 轨迹控制：播放/暂停/重置（仅供演示者）
- 定位状态：校准中 / 同步中 / 精度不足 / 未授权 / 模拟定位。
- 数据：`scenes`、`interactionPoints`、`activeThemeId`。
- 验收：角色+助手同屏；定位轨迹平滑驱动；无移动轮盘（默认）。

### 2.3 线下智游向导（定位/AR 导航，降级/占位）
- 目的：真实到场的定位 + AR/全景导航。
- 核心元素：
  - 授权定位 → 全景图 → 厘米级 AR 全景导航
  - 虚拟向导（可选动漫 IP 陪伴导游）
  - 第一人称 / 第三人称视角切换
  - 箭头引导 + 向导跟随
  - 停留 3 秒自动讲解
  - AI 问一问（语音/文字问答，如「雷峰塔有什么传说」「怎么去附近的卫生间」）
  - 一键购买相关商品（周边、门票）
  - 导览方向盘
- 状态：定位未授权/精度不足 → 说明 + 重新授权 / 模拟定位降级。
- 验收：Demo 中至少提供「模拟定位 + 轨迹」降级入口。

### 2.4 热门浏览路线
- 目的：路线推荐 + 途经景点导航。
- 核心元素：地点 + title + 热度、热门浏览路线、徒步路线（小猪线/异形线/爱心线）、西湖十景路线。
- 状态：与线上全景漫游页面近似。
- 优先级：非 P0，可后续补充。

## 3. 互动模块

### 3.1 热点系统
- 三类：景点 / 游戏 / 场景传送。
- 三段感知：
  | 状态 | 表现 |
  | --- | --- |
  | 远距离 | 不显示或弱方向提示 |
  | 感知范围 | 显示名称和距离 |
  | 可交互范围 | 点选后高亮 + 主操作按钮 |
- 主操作文案：景点 `了解这里` / 游戏 `开始挑战` / 传送 `进入场景`。
- 规则：同一时刻仅一个热点成为主焦点；离开范围恢复弱状态。
- 数据：`interactionPoints`，仅渲染 `enabled === true`。

### 3.2 景点故事浮层
- 目的：在场景内查看文化信息，关闭后回原位置。
- 核心元素：名称、简介、图片、关闭。
- 状态：打开 → 暂停移动/弱化 HUD → 关闭回原位。

### 3.3 主题切换
- 目的：一景多主题（默认西湖 / 中秋雅集 / 国庆主题）。
- 核心元素：主题选择、应用、加载反馈、成功反馈。
- 规则：
  - 只显示 `availableThemeIds` 中的主题
  - 切换改变天空、环境光、装饰资产、氛围
  - 位置、任务、奖励**不重置**
  - 失败时保持原主题
- 数据：`themes`、`activeThemeId`、`availableThemeIds`。

### 3.4 小游戏（猜灯谜）
- 目的：轻量互动，具备开始/过程/失败/成功状态。
- 核心元素：题目、选项、提交、失败重试、成功。
- 数据：`miniGames`（用 `miniGameId` 查找玩法；`rewardId` 查找奖励）。
- 规则：玩法、投放点、奖励不混为一个对象。

### 3.5 奖励（月映断桥）
- 目的：完成反馈，写入进度。
- 核心元素：纪念卡、成功文案、继续游览。
- 数据：`rewards`；写入 `UserProgress.unlockedRewardIds`。

## 4. 身份与收集

### 4.1 我的 3D 形象
- 目的：打造云游分身。
- 核心元素：自拍生成 3D 数字人（第一人称沉浸）/ 选择预设形象（登山者、清风、文乥学等）。
- 优先级：非 P0，可 Mock。

### 4.2 虚拟向导 / 云游搭档
- 目的：助手角色陪伴、引导、提示。
- 核心元素：选择搭档（不同搭档不同特性：知识/趣味/摄影/专业领队）、跟随、领路、提示。
- 优先级：P0 简化（一个默认助手，跟随 + 领路 + 提示）。

### 4.3 背包
- 目的：收集物品、模型、奖励。
- 核心元素：收集里程碑、我的背包、探索者等级、照片、3D 模型、道具。
- 数据：`UserProgress`（`completedInteractionIds`、`unlockedRewardIds`、当前角色位置/场景/任务状态）。
- 优先级：P0 简化（展示已解锁奖励即可）。

## 5. 创作与分享（Mock）

### 5.1 拍照 / 3D 扫描
- 目的：环绕物体/空间拍摄，生成 3D 模型存入背包。
- 核心元素：围绕物体缓慢移动、8 张照片重建、识别提示。

### 5.2 新建 3D 资产 / 上传视频
- 目的：上传景区视频，AI 重建高保真 3D 游览资产。
- 核心元素：选视频文件（MP4/MOV，≤10 分钟，≤2GB）、现场拍摄、拍摄指南。

### 5.3 景区编辑器
- 目的：节日装扮 / 环境编辑（当前效果、云海、云朵密度、雾气、色调等）。
- 说明：与 Admin 的「节日装扮」对应，Client 侧可仅作预览/占位。

### 5.4 分享
- 目的：分享 3D 场景/游记。
- 核心元素：分享文案、朋友圈、保存本地、立即分享。
- 优先级：非 P0。

## 6. 管理端联动（Client 只读）

- 管理端（Admin 工作台）：当前景区/主题/场景/互动点概览、3D 景点资产、节日装扮、活动管理、配置互动游戏、上传视频、新建 3D 资产。
- Client 不实现管理界面，仅消费 `GET /api/client/config`，通过 `version` 变化同步。
- 联动链路：
  ```text
  Admin 修改 → Draft → 发布 → POST /api/admin/publish → version+1
  → Client 轮询 → 仅 version 变化时替换配置/应用主题/刷新热点
  ```

## 8. Client 必须实现的行为（开发约束）

1. 建立 `ClientConfigService`，只封装公共配置接口。
2. 建立 Config Provider/Store，与用户运行状态分离。
3. 首次加载 `GET /api/client/config`，然后 version 轮询。
4. 按 `activeThemeId` 应用默认主题；选择器只显示 `availableThemeIds`。
5. 只渲染 `enabled === true` 的 `InteractionPoint`。
6. 用 `miniGameId` 查 `miniGames`；用 `rewardId` 查 `rewards`；三者不混。
7. 独立维护 `UserProgress`（完成互动、已解锁奖励、位置、场景、任务状态）。

## 9. 建议开发顺序

1. 路由、页面壳、统一 JSON 与共享状态。
2. Aholo 场景接入，游客/助手角色、第三人称相机、模拟定位轨迹。
3. 热点、景点故事与场景返回。
4. 默认/中秋主题切换。
5. 猜灯谜、奖励与游客进度。
6. 管理工作台、主题/互动点配置与发布联动。
7. 补齐加载、错误、降级与目标设备走查。
